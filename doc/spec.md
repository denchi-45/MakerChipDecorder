# MakerChip デコードシステム ソフトウェア仕様書

## 1. システム概要
本システムは、カメラ搭載マイコン（M5Stack Atom S3R-CAM等）を用いて、所定の位置に置かれた「MakerChip」を撮影・解析し、物理的なビットパターンからロット番号およびシリアル番号をデコードして、表示デバイスへ結果を出力する組み込み型検査・展示装置である。

## 2. ハードウェア構成
- **メインプロセッサ/カメラ:** M5Stack Atom S3R-CAM (ESP32-S3)
    - *検討:* 処理負荷が高い場合は M5Stack Tab5 (ESP32-P4) への移行を検討する。
- **ディスプレイ:** GrassUnit2 (レトロ調UI表示用)
- **固定ジグ (推奨):**
    - チップをカメラの画角中央に一定の距離で固定するガイド。
    - 外部光の影響を最小限にするための簡易的な暗箱構造と、均一な照明（内蔵LED等）。

## 3. データフォーマット仕様 (36-bit)
チップ外周（円周36分割、1スロット=10度）のビットを時計回りに評価する。

| ビット範囲 | 項目 | ビット数 | 内容 |
| :--- | :--- | :--- | :--- |
| `[0-3]` | **マーカー** | 4 bit | 常に `1111` (赤色ペイント箇所)。読み取り開始位置の特定に使用。 |
| `[4-11]` | **ロット番号** | 8 bit | 0 〜 255 |
| `[12-35]` | **シリアル番号** | 24 bit | 0 〜 16,777,215 (総チップ数) |

- **物理定義:**
    - `1`: 赤（マーカー）
    - `1`: 緑（OnBitコンポーネントが結合されている状態）
    - `0`: 黒（OffBitコンポーネントが結合されている状態）

## 4. デコード・アルゴリズム (軽量版)
ESP32-S3のリソースを最適化し、高速な応答を実現するための手順。

### Step 1: 前処理
1. **解像度設定:** QVGA (320x240) または QQVGA (160x120) を使用。
2. **チャンネル分離:** 画像をR,G,Bの3chに分離し、各チャンネルごとの輝度分布を解析する。

### Step 2: サンプリング
1. **固定座標抽出:** ジグを使用する場合、チップの中心 $(X, Y)$ およびサンプリング半径 $R$ を定数として定義する。
2. **円環プロファイル:** 中心 $(X, Y)$ から半径 $R$ の円周上を、三角関数（LUT: Look-Up Tableを使用）を用いて360点（1度刻み）サンプリングし、R, G, B各チャンネルの輝度配列を取得する。
   - **白色区切り線の活用:** ビット間にある白色の区切り線はR,G,Bすべてが高い値を示すため、サンプリング位置の微調整やビット境界の特定にBlueチャンネルの情報が有効である。

### Step 3: ビット判定
1. **正規化:** 360点の輝度データから、10度（10ピクセル分）ずつの区間平均を算出。
2. **1/0変換:** 各チャンネル全体の平均輝度（閾値）を基準に、各区間を `1` または `0` に変換。
   - Rチャンネル: マーカー（赤）の判定に使用。
   - Gチャンネル: データビット（緑）の判定に使用。
   - Bチャンネル: 区切り線（白）の検出やキャリブレーションに使用可能（デバッグ出力中）。

### Step 4: パターンマッチング
1. **マーカー探索:** 配列内から `1111` のパターンを検索し、その開始位置をインデックス `0` とする。
2. **ビットシフト:** 見つけた開始位置に基づき配列をシフトし、ロットおよびシリアル部分を抽出。
3. **数値化:** ビット演算により整数値（`uint8_t`, `uint32_t`）に復元。

## 5. デバッグ機能
解析の透明性を高めるため、以下の情報をシリアル出力(115200bps)に定期的に出力する。
すべてのデータ行は、フィルタリングを容易にするために `DATA,` というプレフィックスで始まるCSV形式となっている。

### 5.1 出力内容
1. **サンプリング値 (R_SAMPLED, G_SAMPLED):** 
   - 形式: `DATA,R_SAMPLED,val1,val2,...,val360`
   - 円周上360点の各チャンネル輝度値（0-255）。
2. **ヒストグラム (R_HIST, G_HIST):**
   - 形式: `DATA,R_HIST,count1,count2,...,count32`
   - 360点の輝度分布。8刻み32ビン（0, 8, 16, ..., 248）。各ビンのカウント値。
3. **二値化閾値 (R_THRESHOLD, G_THRESHOLD):**
   - 形式: `DATA,R_THRESHOLD,value`
   - サンプリング値の平均から算出された、現在の判定しきい値。

### 5.2 出力頻度
- 約3秒に1回。

## 6. UIおよび状態遷移
GrassUnit2のレトロな表示特性を活かした設計。

1. **IDLE (待機):** `> INSERT CHIP...` を点滅表示。カメラの平均輝度変化を監視。
2. **SCAN (解析):** 輝度変化検知後、数フレームを解析。 `> ANALYZING...` とプログレスバーを表示。
3. **RESULT (成功):** デコード値を表示。

   [ DECODED ]
   LOT: 012
